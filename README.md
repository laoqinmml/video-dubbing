# 中文视频英文配音流水线

把**中文口播视频**批量转成**英文配音成片**：克隆原说话人的音色，文案改写为**直接面向海外买家**，用自然语速铺满整条时间线，每条只输出一个 MP4。

面向外贸工厂、B2B 制造业、跨境电商的**短视频出海**场景（抖音竖屏 → Facebook / TikTok / Instagram）。

---

## 它解决什么问题

中文短视频要投海外，人工做法是三件事：**翻译 → 找配音 → 对时间轴**。三个环节都是外包，慢、贵、且容易翻错。

这套流水线把三件事一次做完，并且处理了几个**中文转英文特有的硬骨头**：

| 难点 | 处理方式 |
|---|---|
| **受众反了** | 很多素材原本是对**国内出口商**说的（"做外贸的朋友们，想找货源"）。直译过去，海外买家会觉得你在跟他讲他的出口生意。工具会**把受众扭转为海外买家本人** |
| **数字读错** | `20,000` 会被逐位读成 "two zero zero zero zero"；且它在词数预算里算 1 个词、读出来是 2 个词，**所有长度计算都会偏**。工具在**翻译阶段就写成 `twenty thousand`** |
| **中文信息密度高于英文** | 同样的内容，英文要更多词。装不下时工具会**按卖点优先级删句**，而不是加快语速 |
| **合成的不确定性** | 同一段文本，MiniMax 每次时长波动 **±10%**。工具跑多轮、按"最多能填到多少"评分取最优 |

---

## 效果

以 7 条东南亚素材（18.7s – 42.1s）为例：

| 指标 | 结果 |
|---|---|
| 铺满度 | 93 – 99%（末尾由背景音乐补足）|
| 语音处理 | **零变速**（纯 MiniMax 原始输出，无 atempo 痕迹）|
| 中文残留 | 无 |
| 受众 | 全部改为直接对海外买家说话 |
| 单条成本 | **¥0.3 – 1.1** |
| 单条耗时 | 约 20 – 60 秒（不含人声分离）|

## 工作原理

```
中文视频
   │
   ├─ 1 提取 ──── ffmpeg 抽音频 + demucs 分离人声（提高识别率）
   │
   ├─ 2 识别 ──── 火山引擎词级语音识别 → 中文分句时间轴（精确到词）
   │
   ├─ 3 翻译 ──── DeepSeek 改写为英文（受众切换 / 卖点筛选 / 数字写单词）
   │
   ├─ 4 合成 ──── MiniMax 克隆音色整段合成
   │              → 实测时长 → 不够就扩写 / 超了就删句 → 重新合成
   │              → 多轮取最优
   │
   ├─ 5 铺设 ──── 按时间轴落位 + 句界插入停顿 + 生成字幕（真实词级时间戳）
   │
   └─ 6 混音 ──── 背景音乐（计数轮换）+ 响度归一 → MP4
```

**断点续跑**：任何阶段失败，重跑同一条命令即可，已完成阶段自动跳过。且会校验"**产物是否比输入新**"——避免静默交付旧稿配音。

## 快速开始

### 第一步：克隆音色（一次性）

准备一段**干净的原声**（10 秒以上、无背景音乐），然后：

```powershell
python scripts\clone_voice.py --ref "D:\素材\原声.mp3" --voice-id "MyVoice01" --no-prompt
```

> `--no-prompt` 很重要：带参考片段的克隆会**在每句前面串词**（实测过，整句被前缀污染）。

音色信息会写入 `work/voice.json`，之后所有视频共用。

### 第二步：跑一条

```powershell
python scripts\dub.py --src "D:\素材\视频.mp4" --slug "test01"
```

产物：

| 位置 | 内容 |
|---|---|
| `out/test01_EN_dubbed.mp4` | **成片** |
| `out/test01_EN.srt` / `_ZH.srt` | 中英字幕 |
| `work/batch/test01/REPORT.md` | 耗时、合成轮次、成本 |

### 第三步：批量

对每条视频重复第二步即可（音色复用，不必重新克隆）。建议**先用一条跑完整流程给客户确认**，确认后再批量 —— 音色、语速、音乐、停顿都确认过，返工成本最低。

## 常用参数

| 参数 | 作用 |
|---|---|
| `--src <路径>` | 源视频（必填）|
| `--slug <短名>` | 输出文件短名，默认取文件名 |
| `--until translate` | **只出文案不合成** —— 给客户审稿用 |
| `--from fit` | 从合成阶段开始（改过文案后用）|
| `--force` | 忽略已存状态，全部重跑 |

### 审稿流程

`--until translate` 跑完后，用审稿脚本生成"英文 + 中文回译 + 中文原文"对照表：

```powershell
python scripts\review_sheet.py
```

会在项目根目录生成 `待审文案.md`。

## 可调配置

改 `scripts/config.py`，或用环境变量覆盖：

| 环境变量 | 默认 | 说明 |
|---|---|---|
| `ATEMPO_MAX` | `1.0` | **变速上限，已禁用**。不要为了铺满而让人说得更快 |
| `EXTRA_PAUSE` | `0.12` | 每个句界插入的停顿（秒）|
| `HEAD_PAD` | `0.30` | 开头留白 |
| `SD_BAR` | `6.0` | 节奏均匀度合格线 |
| `DUB_BGM` | — | 指定背景音乐，覆盖自动轮换 |
| `DUB_ROOT` | 项目根 | `work/` 与 `out/` 的位置 |

`config.py` 里另外几个**不要随意改**的项：

| 项 | 值 | 原因 |
|---|---|---|
| `PITCH_LIFT` / `PITCH_JITTER` | `0` / `0` | 用克隆的自然音高。调高会让音色变尖（实测 pitch=3 时频谱重心 +30%）|
| `UNIFORM_PACE` | `True` | 全程统一语速 |
| `BGM_GAIN` | `-23 dB` | −21 太响、−26 太轻 |

## 必读经验

`docs/LESSONS.md` 有 18 条，**每条都对应一个真实事故**。最容易踩的六条：

1. **受众要切换，不只是翻译。** 规则在 `translate.py` 的 `SYSTEM_FILL` 里。新素材受众不同时，**先改这段提示词再跑翻译**。
2. **数字在翻译阶段就写成英文单词。** `20,000` 算 1 个词却读成 2 个词，会让所有长度计算偏掉。
3. **atempo 已禁用。** 不要为了铺满而让人说得更快，要把文案压短。
4. **句界拼接必须加淡入淡出。** 切点取自词级时间戳，落在非零波形处，不加淡变会产生咔哒声。
5. **验收音频瑕疵不能只看全文件最大跳变。** 会被源文件的更大跳变掩盖，要看跳变分布。
6. **断点续跑必须校验产物比输入新。** 否则会静默交付旧稿配音。

## 作者踩过的坑（选录）

这套工具是**逐轮实测 + 客户反馈**磨出来的，几个典型：

| 事故 | 根因 |
|---|---|
| 成片念的是**被废弃的初稿** | 断点续跑只看文件存在，没校验产物比输入新 |
| 客户听出**咔哒声**，"像剪辑没剪干净" | 句界硬拼接无淡变。而我最初的检测方法用错了指标，测出"没问题" |
| 客户说**"语速太快"** | 我为填满时间线把变速上限抬到 1.22 |
| 三条视频**结尾被裁** | 删句兜底的判断条件用错了参考值，静默失效 |
| 前 7 条里 **5 条撞同一首配乐** | 用文件名哈希分配，分布不均 |
| 音色**变尖** | 用 `pitch` 参数去对齐基频 —— 但它只移基频不移共振峰 |
| 每句前面多出**"心中有梦，眼里有光"** | 克隆时带了参考片段，模型把片段文本也念出来 |

## 已知限制

- **中文信息密度高于英文**：少数素材需要在保留核心卖点的前提下删句。工具会自动做，并在报告里记录。此时铺满度可能低于 95%。
- **铺满度**：一般 93–99%，末尾由背景音乐补足。
- **专有名词发音**：念不对的词（如人名）加进 `scripts/synth_single.py` 的 `TTS_RESPELL` 字典即可。**只影响 TTS 输入，字幕不变。**
- **单说话人**：音色克隆是单人模型，多人对话视频需要分别处理。
