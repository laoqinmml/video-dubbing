# 中文视频转英文配音 · 使用说明

把中文口播视频转成**英文配音成片**，用克隆的原说话人音色，输出单个 MP4。

---

## 一条命令

```powershell
cd "D:\DeepSeek Harness\中文视频转英文"
$env:MINIMAX_API_KEY = "<MiniMax 国内站 API Key>"
$env:VOLC_API_KEY    = os.environ.get("VOLC_API_KEY", "")

.\.venv\Scripts\python.exe scripts\dub.py --src "<视频完整路径>" --slug "<短名>"
```

产物：

| 位置 | 内容 |
|---|---|
| `out\<短名>_EN_dubbed.mp4` | **成片（唯一交付）** |
| `out\<短名>_EN.srt` / `_ZH.srt` | 中英字幕 |
| `work\batch\<短名>\REPORT.md` | 本条报告（耗时、合成轮次、成本）|

`--slug` 省略时用视频文件名做短名。

---

## 六个阶段（可断点续跑）

```
1 prep       提取音频 + demucs 人声分离 + 记录视频时长
2 asr        火山词级识别 → 中文分句时间轴
3 translate  DeepSeek → 英文文稿（按视频时长给定词数预算；数字写成英文单词）
4 fit        跑 3 轮合成 → 各自实测 → 按"最多能填到多少"评分取最优
             → 略超预算的用 ffmpeg atempo 精确贴合到 100%
5 place      按时间轴铺设 + 写字幕（用真实词级时间戳）
6 mux        配背景音乐 + 响度归一 → MP4
```

**失败后直接重跑同一条命令即可**：已完成的阶段会跳过。若某阶段重跑了，它之后的阶段会自动跟着重跑（依赖链）。

常用参数：

| 参数 | 作用 |
|---|---|
| `--from <阶段>` | 从某阶段开始，如 `--from fit` |
| `--force` | 忽略已保存状态，全部重跑 |
| `--slug <名>` | 指定短名 |

## 关键配置（`scripts/config.py`）

| 项 | 值 | 说明 |
|---|---|---|
| `PITCH_LIFT` / `PITCH_JITTER` | `0` / `0` | **不要动**。用克隆的自然音高 |
| `UNIFORM_PACE` | `True` | 全程统一语速 |
| `FILL_MODE` | `True` | 不追原时间轴，写够字铺满 |
| `WORDS_PER_SECOND` | `2.55` | 词数预算的估算速率 |

环境变量：`SD_BAR`（节奏合格线，默认 6.0）、`CONDENSE_ROUNDS`（精简轮数，默认 3）、`ATEMPO_MAX`（兜底加速上限，默认 1.15）、`HEAD_PAD`（前置留白，默认 0.30）、`DUB_BGM`（背景音乐路径）。

## 重要经验（都是踩过的坑，别改回去）

**① 必须整段单次合成，不能逐句合成。**
逐句合成时每句独立成调，实测词速极差 **80%**（1.77–3.19 词/秒），听起来"有的快有的赶"。单次合成后发音速率在 16 个窗口里 14 个完全一致。

**② `pitch` 参数不要用来对齐基频。**
MiniMax 的 `pitch` 只移基频、**不移共振峰**。实测 pitch=3 时**频谱重心暴涨 30%**，声音变尖。安全区间是 **0–2**，本项目用 0。

**③ 翻译要"先选点后写作"，不能"先全译后压缩"。**
旧提示词让模型全量翻译再压缩，结果 84 词卡死（超预算 25%）。新提示词明确"中文信息量大于能装下的量，请**选择**最强卖点来写"，收敛到 ±1.5%。

**④ 精简只能因为"装不下"，不能因为"节奏不佳"。**
装得下但节奏不达标应该**重合成**；去精简一个长度已经正确的稿子，方向就反了。

**⑤ 时长兜底用 ffmpeg `atempo`，不要用 API 的 `speed`。**
实测 API `speed=1.104` 只缩短 3%（它是表演提示、不是时间伸缩）；`atempo` 是精确的。

**⑥ 标点拼接要按原语义。**
第 8 句以逗号结尾要连到第 9 句，硬改成句号会凭空造出句末停顿；反过来只删句号会产出 `,.` `!.` 这种畸形标点，让模型犯犹疑。

**⑦ "Eva" 要写成 "Eeva"。**
这个中文音色读 `Eva` 不稳定。加 IPA 标注反而更糟（实测判为 /ɛ/）；**改写拼法 `Eeva` 与 /iː/ 相似度 0.772**（裸 `Eva` 仅 0.428）。字幕仍从 `segments_en.json` 取，显示 `Eva` —— 改写只发生在 TTS 输入层。

**⑧ 所有服务直连，必须清掉代理变量。**
火山 / DeepSeek / MiniMax 都是国内直连。继承来的 `HTTP(S)_PROXY` 指向已下线的 10808 会让 SDK 直接报 `WinError 10061`，`dub.py` 已强制清除。

**⑨ 数字必须在翻译阶段就写成英文单词。**
这不只是读法问题，**而是计算问题**：`20,000` 在词数预算里算 **1 个词**，读出来却是 **twenty thousand = 2 个词**。留着阿拉伯数字，**每句含数字的稿子的长度估算从源头就是偏的**。
所以 `translate.py` / `fit_script.py` 的提示词都写死了这条：中文「2万」→ `twenty thousand`，`15年` → `fifteen years`，**output 里不许出现阿拉伯数字**。
`synth_single.py` 的 `spell_numbers()` 只作为最后一道保险 —— 而且它**必须跑在逗号规范化之前**，否则 `20,000` 会先被改成 `20, 000`，正则就匹配不上了（这个顺序错误真发生过，结果 TTS 逐位读 "two zero zero zero zero"）。

**⑩ 合成轮次用"取最优"，不要"逐个判断通过"。**
MiniMax 对同一文本的时长波动达 ±10%（实测同一稿子 26.2s / 25.0s / 33.8s）。逐轮判断通过会来回震荡（实测 92% → 88% → 119%，最后反而落到最差）。
正确做法：**跑满 N 轮，对每个候选算出"最多能填到多少"，取最高者**，超出预算的用 atempo 精确贴合到 100%。

**⑪ `--from <阶段>` 会强制跑该阶段。**
否则 `--from place` 会因为 `en_aligned.wav` 已存在而跳过，**继续用上一次合成音频的旧对齐** —— 这个坑踩过一次。

**⑫ 断点续跑必须校验"产物比输入新"，只看文件存在会静默交付错内容。**
`外贸破壁机14 新加坡` 的成片一度**比音频旧了 44 分钟**：早期一次完整试跑生成了 MP4（用的是被丢弃的初稿），后来重写文案只重跑到 `place`，**mux 没跟着重跑**，交付的视频里念的还是初稿。是靠复听才发现的。
`dub.py` 的 `stage_done()` 现在对 `place` / `mux` / `fit` 都比较 mtime，旧了自动重跑。

**⑬ atempo 已完全禁用（`ATEMPO_MAX = 1.0`）。**
一度为填满时间线把它抬到 **1.22**（最多快 22%），客户立刻听出来："语速太快，原来的语速就好"。降到 1.06 仍被要求禁用。
**不要为了铺满而让人说得更快。** 正确做法是**把文案压短**直到自然语速装得下 —— 代价是铺满度从 100% 降到 93–99%，这是对的取舍。
（`achievable()` 仍保留过冲扣分逻辑：有能装下的候选时一定选它。）

**⑭ 句界拼接必须加淡入淡出，否则一定有咔哒声。**
切点取自 MiniMax 的**词级时间戳**，落在单词真正结束的**前后几毫秒**，波形不在零点。以满幅度接上下一段，信号里就出现**阶跃** → 咔哒声，听感是"剪辑没剪干净"。
`place_single.py` 现在在每个拼接点加 **12 ms 淡出/淡入**。

**⑮ 检测音频瑕疵不能只看"全文件最大跳变"。**
我最初用这个指标判断拼接是否产生咔哒，结论是"完全一致、没问题" —— **是错的**：源文件本身最大跳变就有 0.2863，拼接产生的 0.2 阶跃**被掩盖了**。
**正确做法**：比较跳变的**分布**（如 `>0.15` 的样本数），或直接检查指定位置。修复后成片与源音频的 `>0.15` 样本数完全一致（151 vs 151）。
> 这次是**客户的耳朵**发现了我的检测盲区。

**⑯ 背景音乐默认 −23 dB。**
−21 被反馈"太大"，−26 又"太小"，−23 是中间值。三首曲子按**计数轮转**（`work/bgm_counter.json`）分配到不同视频。

**⑰ 断点续跑必须校验"产物比输入新"。**
`外贸破壁机14 新加坡` 的成片一度**比音频旧了 44 分钟**：早期试跑生成了 MP4（用的是被丢弃的初稿），后来重写文案只重跑到 `place`，**mux 没跟着重跑**，交付的视频念的还是初稿。靠复听才发现。
`dub.py` 的 `stage_done()` 现在对 `place` / `mux` / `fit` 都比较 mtime。

**⑱ 受众是可以切换的，不只是翻译。**
`FB广告用\待翻译视频\东南亚` 这批原本是**对国内出口商**说的（"做外贸出口的朋友们""如果你做外贸"）。英文必须**直接对海外买家**说话。规则写在 `translate.py` 的 `SYSTEM_FILL` 里：**不许出现 exporters / those of you in export / your export market**，改写成 `your market`、`your brand`。新素材如果受众不同，**先改这段提示词再跑翻译**。

**⑮ 写文案时不要逐句对应原文。**
提示词里是 `REWRITE, DO NOT TRANSLATE CLOSELY`：中文哪句在英文里不划算就替换或删掉，**大意相符即可**。同时**每行不超过约 14 词**，超了就拆成两行 —— 长行是合成后节奏赶的主因。允许返回比中文更多的行数。

## 已知限制

- **中文信息密度高于英文**：极少数视频的中文内容量远超英文自然语速能装下的量，精简会停在某个词数。此时走 `atempo` 兜底（上限 1.15），超出会在报告里明确告警，需要人工删句。
- **铺满度**：改造后一般能到 **95–100%**（略超预算的走 atempo 精确贴合）。
  极少数中文内容量特别大的视频会停在 95% 以下，报告里会明确告警。
- **`Eva` 之外的专有名词**若发音不对，加进 `scripts/synth_single.py` 的 `TTS_RESPELL` 字典即可（字幕不受影响）。
