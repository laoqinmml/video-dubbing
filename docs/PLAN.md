# 中文视频 → 英文配音方案
**目标**：把中文视频里的语音转成英文，克隆原说话人音色，并让每句英文的**起讲时间**与原视频基本对齐。
**测试样本**：`外贸破壁机8.m4v`（1080×1920 / 9:16 竖屏，30fps，H.264 + AAC 44.1kHz 立体声，时长 **32.32 秒**，46.3 MB）
**本文档状态**：方案（未开工实现）。所有"可用/不可用"结论都来自本轮**实机实测**，不是推测。

---

## 一、结论先行

### 1. 能不能做？——能，但要拆成两件事
| 需求 | 谁来做 | 结论 |
|---|---|---|
| 克隆原音色、用英文说话 | **MiniMax 音色复刻 + TTS** | ✅ 官方能力，做得到 |
| 音频时间线与原视频对齐 | **我们自己搭**（ffmpeg + 对齐算法） | ✅ 做得到 |
| 一键"视频翻译" | MiniMax **没有**这个接口 | ❌ 必须自己拼流水线 |
| 口型同步（lip-sync） | MiniMax **不做** | ❌ 要做需另接 HeyGen / Wav2Lip |

**MiniMax 开放平台只提供"音色复刻 + 语音合成"，不提供"视频翻译配音"接口。** 时间线同步是本方案的工程量所在，不是调一个 API 就完事。

### 2. 最关键的坑：你贴的 ZenMux key 调不了 MiniMax 音色克隆
实测证据（本轮真实请求）：

| 测试 | 结果 | 说明 |
|---|---|---|
| ZenMux 模型列表里找 MiniMax 语音模型 | ❌ 只有 `minimax-h3` / `h3-max`（视频）、`m2`~`m3`（文本），**没有任何 speech/TTS/克隆模型** | ZenMux 没上架 MiniMax 语音能力 |
| `POST zenmux.ai/api/v1/audio/speech`，model=`minimax/speech-2.8-hd` | ❌ HTTP 404 `invalid_model` | ZenMux 不代理 MiniMax TTS |
| 用 ZenMux key 打 MiniMax 官方 `/v1/voice_clone` | ❌ `status_code 1004 login fail` | 两家 key 体系完全独立 |

**所以：要克隆音色，必须另外给一个 MiniMax 开放平台自己的 API Key。**
- 国内站：https://platform.minimaxi.com （`api.minimaxi.com`）——**音色复刻需完成个人/企业实名认证**
- 海外站：https://platform.minimax.io （`api.minimax.io`）——账号与余额和国内站**不互通**

### 3. ZenMux key 不是没用，它能干别的
它现在**能**做：文本翻译/润色（LLM）、英文 TTS（xAI 音色）、以及你贴的那个视频生成接口。
它**不能**做：语音识别、MiniMax 音色克隆。

**⚠️ 代理是本机最大陷阱（本次踩到并已定位）**
本机所有外网访问必须走 `http://127.0.0.1:10808`。**PowerShell 会自动走系统代理，`curl.exe` 不会**——这导致同一请求用 curl 打全家 500、用 PowerShell 打全部正常，差点误判你给的 key 是废的。
→ 脚本里必须显式设置 `HTTP_PROXY` / `HTTPS_PROXY`（或 curl 加 `-x http://127.0.0.1:10808`）。

## 三、MiniMax 能力边界（官方文档 + 实测）

### 3.1 音色复刻三步
```
① POST /v1/files/upload   purpose=voice_clone   → file_id
   音频要求：mp3 / m4a / wav，时长 10 秒 ~ 5 分钟，≤ 20MB
② POST /v1/voice_clone    {file_id, voice_id}   → 试听音频 + voice_id
   可选 clone_prompt{prompt_audio, prompt_text} 提升相似度（参考音频 <8s）
③ POST /v1/t2a_v2         用上面拿到的 voice_id 合成英文
```

### 3.2 合成参数里对本方案最有用的几个
| 参数 | 取值 | 用途 |
|---|---|---|
| `model` | `speech-2.8-hd`（最新最优） | 音质 |
| `language_boost` | `"English"` | 强制英文发音，专有名词更准 |
| `speed` | `0.5 ~ 2.0` | **压缩英文时长以塞进原时间槽**（比 ffmpeg 变速自然） |
| `emotion` | happy/sad/angry/calm/… | 情绪还原（注：`whisper` 在 2.8 上不支持） |
| `subtitle_enable` + `subtitle_type=word` | 返回**词级时间戳**（毫秒） | 生成英文字幕、做精细对齐 |
| `output_format` | 设 `"url"` 或 `"hex"`，**必须显式指定** | 否则解析错 |
| `pronunciation_dict` | 自定义读音 | 品牌名/型号（破壁机型号、公司名） |

### 3.3 限制（会实际影响排期）
- ⚠️ 音色复刻需**实名认证**，未认证返回错误码 `2038`
- ⚠️ 克隆出的音色属于**临时音色：7 天（168 小时）内未用于任何合成就会被删除**
- 限流：TTS / 克隆 **60 RPM**；同步合成单次最长 **10,000 字符**
- `extra_info.audio_length` 返回**毫秒**——对齐计算的依据
- HTTP 200 ≠ 成功，必须检查 `base_resp.status_code == 0`

## 五、核心难点：时间线对齐怎么做

这是整个方案里唯一的真问题。**中文说 1 秒的内容，英文通常要 1.3~1.6 秒**（音节数差异），所以"起点对齐"和"不拖尾"天然冲突，必须选策略。

### 6.1 三种对齐模式
| 模式 | 做法 | 适用 | 代价 |
|---|---|---|---|
| **A. 起点严格对齐**（口播推荐） | 每段强制放在原 `start`；超长用 `speed`/`atempo` 压到原时长 | 说话人对着镜头讲，观众能看出对不上 | 语速可能被压到不自然 |
| **B. 自然语速 + 顺延** | 不压速，段落依次排布；只在原静音处吸收误差 | 旁白、画面的口型不重要 | 中途开始漂移，越到后面越不同步 |
| **C. 混合（默认推荐）** | 起点仍对齐原 `start`；超长 ≤15% 不处理（吃后面的静音），>15% 才压速；遇大段静音重置 | 大多数实拍视频 | 实现稍复杂 |

**"讲话开始时间基本同步"这个要求，本质是模式 C。**

### 6.2 压速的两条路，优先用前者
- ✅ **MiniMax `speed` 参数（0.8~1.2）**：模型层面重读，自然，无金属音
- ⚠️ **ffmpeg `atempo`（0.9~1.15）**：事后变速，超出范围会失真；只做兜底微调
- 兜底再不行 → 回到 ③ 让 LLM 把译文改短（**最治本**）

### 6.3 翻译阶段就要做"时长预算"（决定成败）
在第 ③ 步的 prompt 里给硬约束：
> 每段英文必须以 ≈2.6 词/秒的常速在 `{原段时长}` 秒内读完；超了就删冗余、合并短句、换更短的表达，不要牺牲意思。

这样第 ⑤ 步大部分段落**天然就合槽**，压速只用于少数几句。

### 6.4 顺带产出
- 中文原文 SRT + 英文 SRT（用 ASR 和 TTS 的时间戳）
- 后期若要精细字幕，可对英文配音再跑一次 ASR 做强制对齐

## 八、风险与限制（提前说清）

1. **口型对不上**。MiniMax 不做口型。你要求的是"讲话开始时间同步"，这个能达到；但嘴型仍是中文的。真要口型同步得另接 HeyGen 视频翻译或 Wav2Lip，属另一个预算档。
2. **英文天然比中文长**。极少数语速很快的原句，压速后仍可能显得赶——只能靠 ⑥ 的"改短译文"解决。
3. **音色克隆 7 天不用会被删**，需要时重新克隆。
4. **克隆相似度取决于原音频质量**。本样本是竖屏口播，若背景有音乐/机器噪音，建议先做**人声分离**再拿去克隆，效果明显更好。
5. **代理依赖**。脚本必须走 `127.0.0.1:10808`，代理挂了全流程会断。
6. **实名认证**。MiniMax 音色复刻未实名认证会直接失败（错误码 2038）。
7. 本机**无 CUDA**，任何本地神经克隆方案都是 CPU 速度，不适合批量。

## 九、验收标准（做完怎么判断合格）
用 32.3 秒样本量化验收：

| 指标 | 合格线 |
|---|---|
| 每句英文**起讲时间**与原句起讲时间偏差 | ≤ **0.3 秒** |

| 音色相似度 | 人工盲听能认出是同一人（≥ 主观"像"） |
| 有无爆音/断裂 | 无 |
| 英文可懂度 | 无漏句、无错译专有名词（品牌/型号需核对） |
