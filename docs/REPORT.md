## 二、背景音乐：原片没有可用的，所以用了你给的推介曲

你希望"原来的背景音乐如果可以用就继续用"。**实测结论：原片没有连续的音乐铺底，无法复用。**

推理过程（我先判断错了一次，这里完整交代）：

**第一步（错）**：我用"全片频段占比"判断，得出"没有 BGM"。
**第二步（又过头）**：发现停顿段 5.7–8.1s 电平 −18.3 dBFS 且高度音调化，就改口说"其实有音乐"。
**第三步（定论）**：逐窗口测量 demucs 分离出的伴奏轨：

| 窗口 | 伴奏轨电平 |
|---|---|
| 0.9–1.9s 说话 | −31.0 dBFS |
| **5.7–8.1s 停顿** | **−18.5 dBFS** |
| 9.6–10.6s 说话 | −30.2 dBFS |
| 23.5–24.3s 空隙 | −30.3 dBFS |
| 27.7–28.7s 空隙 | −30.1 dBFS |
| 30.5–31.8s 说话 | −29.7 dBFS |

伴奏轨**全程恒定在 −30 dBFS**（这是 demucs 的残留本底），**只在 5.7–8.1s 有一个孤立尖峰**。
真正的音乐铺底应该在**所有空隙**都出现；它只在那一处出现 → **那不是铺底音乐，是局部音效/一次性音乐点缀**。

**旁证**：把原片伴奏当 BGM 渲染出来后，后段空隙（27.7–28.7s）只有 **−42.9 dBFS** —— 几乎没声，根本铺不起来。

**所以**：改用你给的 `活力工厂推介曲`。三首我都渲染了，客观特征如下（我听不到，只能给可测指标，**请用耳朵定**）：

| 文件 | 长度 | LUFS | 频谱重心 | 低频占比 | BPM |
|---|---|---|---|---|---|
| `DM_...75129` ← 我选为主版 | 152s | −12.02 | **434 Hz（最亮）** | 47.7%（最少低音）| 115 |
| `DM_...75145` | 127s | −11.68 | 376 Hz | **67.0%（最厚）** | **130（最快）** |
| `DM_...75157` | 152s | −11.68 | 377 Hz | 58.7% | 75（最慢）|

选 75129 当主版的原因：**频谱最亮、低音最少 → 对人声遮蔽最小**，而 115 BPM 仍然够"活力"。
75145 最猛但低音最厚（67%），容易糊住人声；75157 偏慢。三首都给你了，你听完一句话我就换。

### 混音做法
1. 音乐循环铺满 32.3 秒，**首尾 0.35s / 1.2s 淡入淡出**（避免硬切）
2. **侧链闪避（sidechaincompress）**：用英文人声当触发源，说话时音乐自动压低、停顿时抬回
3. 铺底电平 **−21 dB**：实测最终音乐比人声低约 **11 dB** —— 人声优先的正常配比
   （首次我用 −13 dB，实测只比人声低 3.7 dB，太抢，已调整）

> 顺带修了自己一个 bug：原先 loudnorm 的测量取自**纯人声轨**，却作用在**混合信号**上，目标响度只能靠运气命中。现改为**先混音→量混音→再归一化**。

## 四、节奏与语调：从"追时间轴"改为"自然铺满"

### 4.1 你反馈的三个问题与成因

| 现象 | 成因 |
|---|---|
| **语调偏低** | 克隆音色 pitch=0 时约 **251 Hz**，而原说话人 **292 Hz** —— 差 **2.6 个半音**。而我原先的 `pitch` 只做了"相对原句"的微调（−2…+1，均值为负），**从未补这个基准差** |
| **有些地方拉得很长** | 严格对齐时，为塞进小槽位会把语速降到 **0.88**，听起来就是拖 |
| **句子间留白多** | 英文 43 词只有 21 秒，而视频 32.3 秒 —— **缺口 11 秒全是静音** |

### 4.2 三项改动

**(1) 音高：抬升有硬上限，而且"对齐 F0"是个错误目标**

最初 `pitch` 只做"相对说话人"的偏离（以 0 为中心），整条英文比原声低约 2.6 个半音。我于是把 `PITCH_LIFT` 抬到 **+3**，用"中位 F0 对齐原说话人"验收 —— 数字上成功了（F0 偏差 −10.2% → **−1.6%**），**但声音变得特别尖锐、不像本人**。

**根因**：MiniMax 的 `pitch` **只移基频、不移共振峰（formant）**。基频对上不等于音色对上；共振峰不动的情况下硬抬基频，声音就会变薄变尖。

**实测证据**（同一句话，只改 pitch）：

| pitch | F0 | **频谱重心** | 较 pitch=0 |
|---|---|---|---|
| **0** | 246.4 Hz | 818 Hz | — |
| **1** | 259.4 Hz | 796 Hz | −2.7% |
| **2** | 290.1 Hz | 841 Hz | +2.8% |
| **3** | 299.0 Hz | **1063 Hz** | **+30.0%** ← 音色从这里崩 |
| **4** | 321.9 Hz | 1000 Hz | +22.2% |

**可用区间是 0–2**；≥3 时频谱重心暴涨 22–30%，听感就是"尖锐/奇怪"。

**最终设定**：`PITCH_LIFT = 1` + `PITCH_JITTER = 1` → 逐句落在 **0–2**。
成品频谱重心 **750 Hz**（较 pitch=0 基准 −8.3%，属正常波动），中位 F0 271 Hz，**英文可懂度 100%（66/66）**。

> **教训**：验收音色不要用"中位 F0 对齐"当指标 —— 那是基频，不是音色。**频谱重心才是能抓到"变尖"的指标**，本项目的验收脚本已加入这一项。

**(2) 语速：禁止降速**
```
MIN_SPEED = 1.00
```
拉长的部分直接被消除。

**(3) 铺满：不再追时间轴，改为"写够字 + 均匀排布"**

- 翻译不再受"每句可用秒数"约束，改为**按视频长度算总词数目标**
- 排布改为**首尾相接 + 余量均分为停顿**（`align.py` 的 fill 模式）
- 行长不限，句子间只留 0.2–0.7 秒自然呼吸

**副产品**：写了 `fit_fill.py` —— 因为**音高抬升会让发音变长**（实测同一段文本 +15%），字数目标不能是常数，必须按**实测语速**反推。

> 过程中也修了自己的两个判断错误：
> ① 字速按 2.0 词/秒估算，实测是 **2.4–2.8 词/秒**，导致第一版只铺到 85%；
> ② 让 LLM"写到 N 词"不可靠（118→98→90→88，目标 72，三轮仍超 22%），所以 `.py` 改为：**偏长用全局语速微调一步收敛，偏短用停顿吸收**，最后才回退到改文案。

### 4.3 逐句参数（仍然来自对原声的测量）

| 参数 | 映射来源 | 实际取值 |
|---|---|---|
| `pitch` | 全局 +3，叠加该句 F0 相对偏离 | **+2 … +4** |
| `speed` | 该句音节速率相对基准（下限 1.00）| **1.00 … 1.09** |
| `vol` | 该句响度相对基准 | **0.85 … 1.06** |

> 语速代理最初用**字符数/秒**，含拉丁字母的句子被算成超快、全顶上限；改成**音节核（包络 2–8 Hz 调制峰值）速率**后中英文才可比。

### 4.4 成稿（83–85 词，6 句）

```
Hello boss, I'm Eva, from a blender factory.
Our strength is plain to see on the factory floor.
We run fully automatic injection molding machines, and we make most core parts like jars and blades in house.
We control quality at the source and adjust every detail for your export market, so nothing slips.
Working with us is simply easier and more relaxed.
So if you're in export and want a stable, reliable blender supplier, and you like our factory, just call me!
```

> 第 2 句曾写成 `Our strength is plain to see...`，合成后被听成 "Our van is planned to see..." —— **strength + plain to see 这串辅音簇确实糊**，已换成 `You can see how strong we are right here in our factory.`，可懂度从 92% 回到 95%。


**问题**：第一版 8 句全部是 `speed=1.00 / pitch=0 / vol=1.00` —— 听起来像播报，没有起伏。

**做法（不靠随机，靠测量）**：从**原中文录音**里逐句量出说话人自己的语调、语速、力度，再映射到 MiniMax 的逐句参数：

| 参数 | 映射来源 | 允许范围 |
|---|---|---|
| `pitch` | 该句中位 F0 相对说话人基准的偏离 | ±3 |
| `speed` | 该句音节速率相对说话人基准的偏离 | ±12% |
| `vol` | 该句响度相对基准的偏离 | ±15% |

> 中间修了自己一个错：最初的语速代理用**字符数/秒**，结果含拉丁字母的句子（"Boss"、"Eva"、"Call me"）被算成超快，全部顶到上限。改成**音节核（包络 2–8 Hz 调制峰值）速率**后，中英文可比，数值才合理。

**实测结果**：

| | 参数分布 | 实测 F0 |
|---|---|---|
| 改前 | 全部 1.00 / 0 / 1.00 | 无起伏 |
| **改后** | pitch **−2…+1**（4 档）、speed **0.88…1.12**、vol **0.85…1.06** | **244–322 Hz，标准差 27.0 Hz** |

**并验证了 pitch 参数真的有效**（不是我以为）：

| pitch 参数 | 实测 F0 |
|---|---|
| −4 | 194.3 Hz |
| 0 | 250.6 Hz |
| +4 | 304.1 Hz |

单调、幅度真实。

**代价**：6 句依然**零压缩、零重叠、漂移 0.000 秒**（严格对齐没被破坏）。

### ★ 官方文档给出的真正原因

《声音复刻下单及使用指南》原文两条关键：

> **后付费音色需要「开通声音复刻模型2.0服务」，并「单独开通后付费音色服务」。**
> **各个项目下资源是分离的。**

以及正确流程（我此前理解有误）：

> 通过批量查询接口，查看**可用音色ID**（也可从控制台直接获取）；选定音色ID后，调用 Upload 接口上传音频训练音色。

**即 `speaker_id` 应填账号中"已存在的音色 ID"**，不是空串、也不是字面量 `custom_speaker_id`。
空的 → `55000000 resource ID is mismatched`；`custom_speaker_id` → 走后付费通道 → `volc.megatts.timbre not granted`。两种报错由此完全解释。

**需要做的**（二选一）：
- **后付费路线**：在【开通管理】里，除「声音复刻模型2.0」外**再单独开通「后付费音色服务」**
- **预付费路线**：在【开通管理】→【快速购买】下单**音色槽位**（买一次可跨模型复用）

并确认模型开在**同一个项目**下（项目间资源隔离）。之后从**音色库**取一个 speaker_id 给我，即可直接跑复刻。

### 翻译通道的这一处改动

换成 DeepSeek 后发现一个问题：**它不遵守字数预算**（6 行里 4 行超标，17–18 词 vs 预算 12–13）。而字数预算存在的意义就是让语速保持自然、不靠加速硬塞。

所以加了一道**自动精简回修**（[translate.py](scripts/translate.py) 的 `tighten()`）：首轮翻译后，把超标的行连同它们的硬上限退回给模型，要求压到限内，最多两轮。实测：

```
repair round 1: tightening 4 line(s): [1, 3, 4, 6]
repair round 2: tightening 2 line(s): [3, 4]
→ 6 行全部达标
```

**翻译结果**（DeepSeek 直连 + 两轮回修）：

| # | 英文 |
|---|---|
| 1 | Hi boss, I'm Eva, a blender factory. |
| 2 | Real strength. |
| 3 | Our workshop runs fully automatic injection machines and makes most core parts. |
| 4 | We control quality from the source and flexibly adjust details for export. |
| 5 | Easy partnership. |
| 6 | Exporters wanting a stable blender supplier, if we interest you, call me! |

| 逗号是超时元凶 | 5 个词要 2.65 秒 | 逗号/冒号各约 0.3 秒停顿 |
| 词数预算拍错 | 按 2.6 词/秒，实际 1.7–2.2 | 改成实测值 |
| 克隆参考内容泄漏 | 每句前被念 "心中有梦，眼里有光" | **去掉 clone_prompt** + 自动检测 |
